# 量化验收指标：怎么算、阈值怎么定、怎么复算

> 原则：**每个"感觉"都要换成一个能量出来的数**。
> 阈值不是拍脑袋定的，是**看实测分布的空档**定的 —— 每条下面都写了怎么定阈值。
> 脚本在 `scripts/`（依赖与改造说明见 `scripts/README.md`）。

## 1. 镜长中位数（"碎不碎"的验收）

**反馈原话**：`"感觉有点碎"` `"我没看够就切下一个镜头了"` `"切碎了就不太沉浸"`。

### 怎么算

- **只算实拍镜头**：照片卡与滚屏卡不算"镜头时长"。
- **只算中位数，不算平均数**：平均数会被开场那几刀和个别超长镜（20s+）带偏。
- **开场和正文分开算**：开场本来就该是快切，混在一起算会把结论算反。
  - 开场 = 段落名以"开场"开头的行
  - 正文 = 段落名以"第"开头的行
- **用"真正渲染的那份分镜表"**：如果成片里还插了别处的镜头
  （例如另一台相机拍的 2.8–3.6s 插入镜），要用**含插入镜的那一版**来算，
  否则中位数会偏高。

```python
def dur_of(r):
    if r.get("photo") or r.get("card"): return None      # 静帧/滚屏卡不算
    return float(r["tout"]) - float(r["tin"])
```

### 阈值怎么定

不看绝对数，看**版本之间的梯度**与**"≥8s 的镜数"**。实测：

| | 正文镜数 | 正文中位 | 正文平均 | ≥8s |
|---|---|---|---|---|
| 短版 改前 | 15 | 7.0s | 7.2s | 7 |
| **短版 改后（主推）** | **12** | **10.0s** | **9.0s** | **9** |
| 中版 改前 | 22 | 5.5s | 6.2s | 7 |
| **中版 改后** | **16** | **8.0s** | **8.0s** | **9** |
| 长版（未改） | 38 | 6.0s | 6.2s | 12 |

- 三版形成清楚梯度：**越短镜头越长**。
- 开场三版都是 **1.5s 中位**（快切保留存率）。
- **关键判据是"改后 7.0s vs 长版 6.0s 几乎没区别"** ——
  这说明改动**没有效果**，别被"我把每条都拉长了"骗过去。

## 2. 拉普拉斯方差（锐度）

### 怎么算

对每帧算 4 邻域拉普拉斯，取方差；**逐帧算完取中位**；全部在 **1080p** 上比。

```python
k = np.array([[0,1,0],[1,-4,1],[0,1,0]], dtype=np.float32)
lap = (f[1:-1,1:-1]*k[1,1] + f[:-2,1:-1]*k[0,1] + f[2:,1:-1]*k[2,1]
       + f[1:-1,:-2]*k[1,0] + f[1:-1,2:]*k[1,2])
out.append(lap.var())          # 最后取 np.median(out)
```

解码路径：`ffmpeg -vf scale=1920:1080 -pix_fmt gray -f rawvideo -`。

### 阈值怎么定

**不要用绝对量级**（不同素材差异巨大）。用**相对参考**：以"源 4K → 1080（不裁不稳）"为 100%。

| 配置 | 绝对（拉普拉斯方差） | 相对 |
|---|---|---|
| 源 4K → 1080（参考） | 4444.7 | 100% |
| 只裁 1.08、不稳定化 | 4181.6 | **94%** |
| 裁 → 1080 → 稳定化（旧） | 3080.8 | **69%** |
| 裁 → **4K 稳定化** → 1080（现在） | 3316.1 | **75%** |
| 同链但 `interpol=lanczos` | 2119.4 | **48%** |

**判据**：掉到 **~69%** ⇒ 稳定化在输出分辨率上做了逐帧重采样。
另外两个可读结论：
- **94% 说明"裁切本身"只损失 6%**——所以"糊"不是裁切的锅；
- **lanczos 只有 48%**，比 bicubic(75%) **明显更糊**，所以 `interpol` 不要换。

**关键用法：必须有"不做处理"的对照组才能解读跌幅。** 单独的 3080.8 没有意义。

> ⚠️ **更正（返工后）**：这一节原来把 **75%** 当成"更好的配置"，
> 并据此得出"稳定化要放在源分辨率（`scale` 之前）做"。**这条结论已作废**：
> 那 75% 是把"在 1280 上检测的 trf"施加到 4K 上造成的**过校正**（修正量 3×），
> 交付后表现为"**感觉空间在波动**"。**运动正确性优先于这 9% 的锐度**——
> 见 SKILL.md T5 与本文 §3.3。锐度指标仍然有用，但它**不能单独用来选稳定化方案**。

> 注：`scripts/sharp_check.py` 里的对照项用的是 `interpol=2`(lanczos)，
> 而生产链用的是 `interpol=1`(bicubic)；另外该脚本的 docstring 里有一句
> "bicubic 比 lanczos 软"，与实测结论**相反** —— **以本手册/实测为准**（见 §9 未核实清单）。
> ⚠️ "锐度提升 **+12~22%**" 这个说法**只出现在一次汇报文本里、没有复算记录**，
> 可复算的是 **69% → 75%**——但**这两个数都不该再当成改进目标**（见上）。

## 3. 相位相关抖动

### 怎么算

把窗口解成 **480×270 灰度、`fps=30`**，逐帧用**相位相关**估全局平移 `(dy,dx)`：

```python
F1 = np.fft.rfft2(f1 - f1.mean()); F2 = np.fft.rfft2(f2 - f2.mean())
R = F1 * np.conj(F2); R /= np.abs(R) + 1e-9
c = np.fft.irfft2(R, s=(H, W))
# ⚠️ 峰值必须只在中心 ±SEARCH（实测 ±24px）的窗口里找：
win = c[H//2-SEARCH:H//2+SEARCH+1, W//2-SEARCH:W//2+SEARCH+1]
iy, ix = np.unravel_index(np.argmax(win), win.shape)
dy, dx = iy - SEARCH, ix - SEARCH
```

> **为什么必须限制搜索窗**：在全图上取峰，噪声峰会被选成"峰值"，
> 给出几十像素的**荒谬位移**（这类异常值会把 std 整个带飞）。±24px 是实测够用又稳的窗宽。
>
> ⚠️ **限制窗宽的同时必须 `fftshift`**：`irfft2` 的零位移在**第 0 个索引**，
> 不是画幅中心。少了这一步，窗就开在"半帧位移"处，**静止画面也会量出十几像素**。
> 这一条是**真的踩过**的，见 §3.3。

然后**分离高频抖动与有意运镜**：

```
d        = 逐帧平移序列
hf       = d − moving_average(d, 15帧 ≈ 0.5s)
shake_px = std(hf) * 1920              # 折算到 1080p 画幅上"每帧抖多少像素"
pan_px_s = |mean(d)| * 1920 * 30       # 有意为之的运镜速度
```

**为什么不直接用稳定化滤镜自己导出的运动文件**：
用"稳定化滤镜的调试输出"算**绝对**运镜速度，实测得出 **86000 px/s** 这种不可能的数值
→ **那类文件的列单位与假设不符**，所以**不作为判据**，只留作"查看单条素材运动"的工具。

另有一个更早的实现：跑稳定化**检测**阶段拿到逐帧全局运动，
取相邻帧平移量差分的 RMS（`sqrt(mean(dx_diff² + dy_diff²))`），
在 **480 宽**归一的像素尺度上；平稳摇镜的差分小、手持抖动的大。
这是**无量纲相对量**，能用。

### 阈值怎么定

**没有文档化的绝对阈值**（这条要诚实）。
用途只有两个：**排序**（哪条更抖）和 **A/B**（改滤镜顺序/参数前后同窗口比较）。
如果要定阈值，做法和下面水/风比一样：
**对同一批素材量出分布，找"人眼看着就是抖"和"看着是稳的"之间的空档。**

> ⚠️ **一条"想清楚了对、但当时没测对"的相对判据**（返工后补的）：
> **稳定化版本的高频残差必须低于"不做稳定化"的对照**，否则它不是没减震，就是在**加震**。
> 判据本身没问题，但当时用来支撑它的那组数字是**噪声底**（见 §3.3 的更正）：
> **先把"静止画面 = 0"验出来，再用这个判据。** 绝对阈值仍然没有。

### 3.2 闪烁 / 抖动：静态区域帧差 MAFD（**比相位相关更便宜、更直接**）

**怎么算**：选一块**画面里本来应该静止的区域**（实测用的是"天空带"），
量**相邻帧的平均绝对差**（MAFD）。静态区域上的抖动会把它抬高，
而"有意为之的运镜"不会（因为它也移动了静态区域……所以只适合**静止机位/静止区域**的对比）。

**怎么用**：它**单独看没有意义，必须和对照组放在一起**。实测（同一窗口、同一运动文件）：

| 配置 | MAFD（天空带） |
|---|---|
| 旧顺序（稳定化在 `fps` 之后） | **1.815** |
| 新顺序（稳定化在 `fps` 之前） | **1.744** |
| **不做稳定化（对照）** | **1.745** |

结论一眼可见：**旧顺序比"什么都不做"还差**——这就是"闪烁"的量化证据。
（顺带说明：新顺序只是"不比不做更糟"，因为那条素材本身机位就稳，
稳定化在它上面本来就没多少事可做。**指标必须带对照组才能这样解读**。）

**另一条可用的数值**：对逐帧姿态序列算抖动，得到某条素材 **0.55 °/帧**，
而其余在 **0.02–0.07 °/帧** —— 明确的离群值。
（注意：这条用的是某个工具导出的姿态数据；同一工具导出的"运镜速度"因为**单位不可信**
算出了 86000 px/s，**不能混用**，见 SKILL.md §11。）

### 3.3 运动残差：逐帧相位相关测**高频残差**（⭐ 返工后新增；**方法可用，但那张表复算不过关**）

**什么时候用**：画面"**感觉空间在波动**"、或要判断"某个稳定化配置到底是减震还是加震"的时候。
它想回答的是唯一一个重要问题：**这次的稳定化是在减震，还是在加震？**

**怎么算**：对**同一段素材**渲**多个版本**（至少要有"**不做稳定化**"的对照），
每个版本都解成 **480×270 灰度**，逐帧相位相关估全局平移（**峰值只在 ±24px 窗口内找**，
**并且要先 `fftshift`**），再取高频残差：

```
c    = fftshift(irfft2(F2·conj(F1)))          # ⚠️ fftshift 不能省，见下
d    = 逐帧平移序列 (dy, dx)                   # 峰值只在中心 ±24px 里找
k    = ones(11)/11                             # 11 帧滑窗 ≈ 高频/低频分界
hf   = d − convolve(d, k, "same")
高频残差 = sqrt(mean(hf²))                      # 单位：480 宽分析尺度上的像素
平均平移 = hypot(mean(dy), mean(dx))            # 确认几个版本比的是同一段运动
```

> ⚠️ **`fftshift` 是这条方法最容易翻车的一步**（真的翻过）：
> `irfft2` 出来的**零位移在第 0 个索引**，不在画幅中心。
> 直接按 `H//2 ± 24` 取窗，窗就落在**"半帧位移"**处，
> 于是**完全静止的画面也会量出十几像素的"高频残差"**——那是噪声底，不是抖动。
> 所以工具里必须带一条自检：**静止序列必须量出 0**（`res_check.py --selftest`）。

**当时测的数**（⚠️ **复算不过关**：那一版**没有 `fftshift`**，
量到的是噪声底；详见下面的更正）：

| 版本 | 镜头 A 高频残差 | 镜头 B 高频残差 |
|---|---|---|
| **不稳定化（对照）** | 12.367 | 13.193 |
| stab@1080（检测 1280 → 施加 1920，**1.5× 失配**） | 12.725 | 14.400 |
| **stab@4K（检测 1280 → 施加 3840，3× 失配）** | 12.438 | 14.369 |
| **stab@1280（施加 = 检测）** | **11.842** | **13.300** |

**复算的结果（修正后，用当年留下的同一批渲染文件）**：

用**当年留下的 12 个渲染文件**（3 条素材 × 4 个版本）重算：
**旧窗把上表逐档复现到小数点后三位**（12.367/12.725/12.438/11.842 与 13.193/14.400/14.369/13.300，
第三条 13.030/13.803/13.500/13.117）—— 这张表确实是那个漏了 `fftshift` 的窗算出来的。
**同一批文件、修正后的数值**：

| 素材 | 旧窗（没 `fftshift`） | 修正后 | 修正后的读法 |
|---|---|---|---|
| 镜头 A（**完全静止**） | 12.367 / 12.725 / 12.438 / 11.842 | **0.000 / 0.000 / 0.000 / 0.000** | 静止画面没有残余抖动，四档**完全一样** |
| 镜头 B（摇镜） | 13.193 / 14.400 / 14.369 / 13.300 | 0.182 / 0.175 / 0.200 / **0.227** | 内容运动占主导，"施加 = 检测"档**最高** |
| 镜头 C（有真实小残余） | 13.030 / 13.803 / 13.500 / 13.117 | 0.363 / 0.360 / 0.394 / **0.332** | 只有它支持结论，但**只低 0.03 px（≈9%），在噪声量级内** |

**怎么读（更正后）**：

- 旧窗在**完全静止**的素材上就给 **12~14 px**，而且**逐档复现了上表** → **上表是噪声底**，
  **不能用来支持"只有施加=检测那一档在减震"**。
- 修正后的正确数值小**两个数量级**（静止 = 0；有残余的两条 0.18~0.39 px）——
  这也说明：**"测得出来"本身要先证明不是噪声底**。
- **"近乎静止的镜头才测得准"这句话要拆开说**：真正**完全静止**的镜头（镜头 A）
  **没有信号**（四档都是 0，无法区分）；**摇镜**（镜头 B）又会被内容运动淹没。
  需要的是"**手持、机位大体不动、但确实有小幅残余抖动**"的窗口——**这种窗口最难挑**。
- **这条规则（施加分辨率 = 检测分辨率）仍然成立**，
  但它的依据是 **trf 的单位**（trf 存的是检测分辨率上的像素量，
  施加在 4K 上就是 3× 修正量），**不是上面那张表**。
- **要重新取证**：按上面那条挑窗口，**必须带"不做稳定化"的对照**，
  并且**先证明数值明显高于噪声底**（`--selftest` 先跑）。

> ⚠️ **"近乎静止"要拆开说**：**完全静止**的镜头没有信号（四档都得 0，无法区分）；
> **行走 / 摇镜 / 车拍**的**内容运动**又会把高频残差淹没（只能看相对排序，绝对值没有意义）。
> 需要的是"**手持、机位大体不动、但确实有小幅残余抖动**"的窗口——
> **选窗口这一步和方法本身一样重要**，而且它比看起来难。
> 另一个会让判断失真的事实：`vidstabtransform` 在残余很小时会**跳过**该帧
> （`debug=1` 能看到 `disabled (19+11)/345, residual: 0.7` 这类行）——
> 本来就稳的素材上它几乎什么都不做。

## 4. 水/风能量比（同期声要不要留）

### 怎么算

在**这条镜头实际使用的那个窗口**上（不是整条素材）量：
`(500–8000Hz) 能量 / (<200Hz) 能量`。

```python
X = |FFT(x * hann(len(x)))|**2 ; f = rfftfreq(len(x), 1/22050)
lo  = X[f < 200].sum() / tot
hi  = X[(f >= 500) & (f <= 8000)].sum() / tot
ratio = hi / (lo + 1e-12)
```

**物理依据**：运动相机的风噪 **90% 以上能量在 150Hz 以下**；
所以 `ratio` 高 = 中高频里有真东西（水声、树叶、脚步、说话）；
`ratio` 低 = 基本只有风噪。

### 阈值怎么定（**这是"看空档"的范例**）

实测分布（重挑素材后重量，按 ratio 降序）：

| # | ratio | 低频占比 | 画面 | 结论 |
|---|---|---|---|---|
| 1 | 0.377 | 60% | 阴暗针叶林里下山 POV | 留（脚步/落叶） |
| 2 | 0.342 | 53% | 针叶林内部长镜 | 留（树声/鸟） |
| 3 | 0.302 | 69% | 出水口泥泞小径 | 留（水声） |
| 4 | 0.220 | 72% | 马帮驮队 | 留（铃/蹄） |
| 5 | 0.165 | 83% | 湖畔土路 | 留（湖水） |
| 6 | 0.163 | 82% | 同伴坐长凳看湖 | 留（水/人声） |
| 7 | 0.077 | 86% | 镜面倒影（静止） | 静音 |
| 8 | 0.067 | 87% | 逆光星芒 | 静音 |
| 9 | 0.066 | 88% | 湖边步道推进 | 静音 |
| … | ≤0.061 | 88–99% | 其余 33 条 | 静音 |

**`0.163 → 0.077` 中间差了整整一倍**，门槛取 **0.12** 落在这条空档里
（≈ −9dB，工具注释里写的就是这个）。

> **反面教材**：留声的那几条里，原始声（未滤波）能量 90%+ 也在 150Hz 以下 ——
> 所以留声之前**必须**高通，否则留下的只是"隆隆声"（见 T12）。

### 复算

```
python scripts/amb_audit.py                    # 合并所有版本的窗口，取每条最长的使用窗口
python scripts/amb_audit.py --sl <分镜表.json>
```

同一个素材用两次只量一次（取最长窗口）。脚本输出一张表 + 建议的"留声清单"。

> **一个值得注意的现象（阈值不是一次定死的）**：**第一轮**用同一判据量出来的是
> `13.56 / 1.15 / 0.30 / 0.23 / 0.22 / 其余 <0.07`，取的门槛是 **~0.15**；
> **重挑素材后重量**，最大的一条降到 0.377，才改成 **0.12**。
> 也就是说：**阈值要随着素材批次重新看分布**，不要把它当常数抄走。
> 两次的共同点才是可迁移的：**在"留声组的最小值"和"静音组的最大值"之间找空档**。

> **量之前先确认"量的是什么"**：曾经量交叉淡化接缝时量到了 **+5dB / −11dB / −6dB**
> 三个离谱的值，逐个排查发现是三个不同的错：
> ① 量到的是**旁白轨**而不是纯配乐床；② 曲子在 54s 就用完了却被铺到 58s（后面是静音）；
> ③ 线性交叉淡化的**固有功率凹陷**。
> **教训：先确认量的对象与假设，再看数字大小。**

## 5. 时长校验

### 5.1 逐段

```
python scripts/seg_audit.py <分镜表.json>
```

对分镜表每一行算"应有秒数"（实拍 = `tout - tin`；照片/卡片 = `dur`），
与**分段文件的实际时长**比，`Δ > 0.25s` 报警；缺分段也报；最后打合计。

### 5.2 拼接后（**最重要的一条**）

`concat -c copy` 会**静默跳过**坏分段。所以拼接后必须比总时长：

- 阈值：`abs(实际 − 分镜表和) > 0.35s` → **直接抛错停**；
- 并把**单段时长 < 0.05s** 的分段列为可疑（那种就是被 kill 掉写了一半的文件）；
- 实测漏网案例：kill 掉渲染后某个分段成了半个文件，成片**少了 12.4s 却不报错**。

### 5.3 解码完整性

```
ffmpeg -i <成片> -f null -
```

要求 **0 条错误**（所有交付版本都跑过）。

### 5.4 时间轴单调性（照片最容易出问题的地方）

**怎么算**：把**全片所有视频 + 照片的拍摄时间戳**按播出顺序 dump 成一行，
检查是否**单调不减**。

**为什么**：镜头本身按叙事重排是允许的，但**照片相对视频**出现时间倒流就是 bug。
实测里照片错位是**四层 bug 叠加**出来的，每层单独看都"不报错"：

1. 照片位置原来是**手写**的，没有程序排序；
2. 加了自动锚定但不生效——**元组解包顺序写反**，锚点永远不命中 →
   表现是"整章照片全被丢到章尾"；
3. 修完解包还是错——时间解析**只认一种格式**，所有视频时间读成 `None` →
   每张照片都锚到最后一条视频；
4. 为保单调加的"排不出正确顺序就宁可不放"这条规则，**把照片整条丢掉了**。

**修法（可迁移）**：把规则从"代码里隐式"变成"**计划文件里的显式字段**"
（给照片一个 `photo_anchor` override，把某张照片钉到某条镜头之后），
并给自动锚定加 **30 分钟容差**（"这个量级的时间倒流看不出来"）。

**怎么验证**：渲染前跑一遍并**打印整条时间轴**；任何一处下降都要求
给出**显式 override 的理由**。

### 5.5 帧率一致性（**所有段同帧率，且用分数**）

**怎么算**：对**每一个分段**（视频段 / 照片段 / 滚屏卡段）与成片各跑一次：

```
ffprobe -v error -select_streams v -show_entries stream=r_frame_rate -of csv=p=0 <文件>
```

要求**全部等于 `60000/1001`**（或你那条链规定的那个分数），**一个字都不能差**。

**为什么要验**：

- `fps=60000/1001` 会被 ffmpeg 原样记成 `60000/1001`；**`fps=59.94` 会被记成 `2997/50`**——
  数值上几乎一样，但和源、和其他段**不完全一致**，拼接 `-c copy` 就会出问题；
- 照片段与滚屏卡段是**脚本生成**的（`color=…:r=<FPS>`），
  改了视频段帧率却忘了重新生成它们，就会得到**混合时基**；
- 硬降帧（59.94 → 30 = **每两帧扔一帧**）是 **judder**，不是抖——别和稳定化的问题混在一起查。

**成片侧的期望值（实测基准）**：4K 母版 `3840×2160` / `60000/1001` / **8840 帧** / 147.7s /
**0 解码错误** / 841 MB；1080p 版 378 MB。体积比 30p 版涨约 **1.8 倍**（正常，不是码率设错）。

## 6. 音频电平

| 量什么 | 怎么量 | 期望 |
|---|---|---|
| 成片整体 | `volumedetect` 的 `mean_volume` | **mean ≈ −19.5 ~ −19.8 dBFS**，max ≈ 0 ~ −0.1 dBFS |
| 原声总线（滤波后） | 同上，加 `-af "highpass…,agate=threshold=-55dB,volumedetect"` | 比配乐床低约 **9dB** |
| **原声是否真的进了成片** | **单独渲染原声轨**再量 | mean **−18.4 dBFS**（≈可闻） |
| 逐镜原声是否生效 | 量**分段文件**的 mean | 留声 −28 ~ −43dB；静音 ≤ −82dB |
| 缓存键是否换了 | 同上，比同一窗口的新旧两份分段 | 旧键 −91.0dB vs 新键 −43.2dB（差 48dB） |

**为什么必须单独量**：整片混音里配乐占主导，**窗口均值只差 0.3dB**，
光看整片电平根本判断不了同期声有没有生效。

**"结尾 1–3 秒安静"不是漏音**：那是配乐的**自然收尾淡出**。
所以检查异常静音段时要排除最后几秒。

## 7. 配乐床接缝

对每个交界点 `c` 量三段 RMS：

```
before = RMS[c−14, c−4]     mid = RMS[c−1.5, c+1.5]     after = RMS[c+4, c+14]
bump   = mid − max(before, after)
```

**判据：`bump < 1.5dB`**，否则标 `⚠`。
同时用累积和算 2s 滑动 RMS，统计 `< −45dB` 的近静音区段数（应为 0 —— 配乐全程有内容）。

**为什么用"相对前后"而不是绝对电平**：配乐本身有动态，
"接缝突起"要和**邻近段落**比才有意义。

配套的参数扫描（这次做过）：

| 交叉淡化半宽 | 结果 |
|---|---|
| 0.5 / 0.8s | 太短，接缝**掉 10dB**（两边都收着，没人填） |
| **1.5s（总重叠 3.0s）** | **采用**，最深接缝 −3.3dB |
| 2.5 / 4.0s | 太长，把开头的留白糊掉 |

段间归一（先归一到统一 RMS 再交叉）的实测效果：**−8.2dB → +0.1dB**。

交付时的实测接缝（等功率淡化之后）：`18.5s +0.8dB`、`71.1s +0.7dB`、
`156.9s −8.8dB`、`195.9s −2.6dB`，**无近静音段**。

> **`−8.8dB` 那一处不是 bug，是刻意保留的**：它落在"低谷章"里，
> 音乐在那里故意沉下去。**所以"接缝电平"要逐处看语义，不能一刀切要求平坦。**
> 判据只能用来抓"**不该出现的**突起/凹陷"。

## 8. 配乐是否"纯器乐"（双证据）

同一段音乐用**两条互相独立**的判据：

1. **语音识别（ASR）** 转写：有念白就会转出文字（实测那一段转出一整句英文，其余各段全空）。
2. **3–6Hz（音节速率）调制**：那一段 **16.19%**，其余段 **0.6–5.9%**。

两条同时命中才能定案（单条可能是误判）。
修完复验：调制 **0.93%**、ASR 空；
交付前对全部分段各跑一遍 ASR，**全部为空**。
